What it is

This is a real-time simulation of a Solari split-flap departure board, like the old ones at Grand Central and Penn Station. It runs in a browser with WebGL through three.js. Everything it needs is in the folder, so it never loads anything from the internet.

Run it: double-click index.html (Chrome or Edge), then click once anywhere. Browsers keep sound muted until you click; a note at the top says so.

Why there's an embedded copy

Chrome and Firefox block fetch() of neighbouring files when a page is opened as file://. The page therefore does this:

  1. It tries the real JSON and WAV files first; this works when served.
  2. If the browser blocks that, it uses embedded.js and says so in the control bar.
  3. The Load JSON… button picks edited JSON files and works from file:// too. It tells fields from schedule by their content: columns+drums means fields, events means schedule.

Behaviour and design decisions

  • Board state at clock time T is every event with t <= T, applied in order. Reset, looping and loading all recompute the state from scratch, so the state is deterministic.
  • Drums only advance forward: changing A to E flips through B, C and D, then stops on E, like a real drum. A change such as E to A wraps around the whole drum. The alnum drum order is space A–Z 0–9 . - & / '. Characters that aren't on a drum show as blanks. Text is shown uppercase (board.uppercase).
  • Flap timing: flapMs is 110 per flap. A1 feedback asked for slower transitions than A1's, and 110 ms is my own choice; A1 and A2's actual values weren't available. The leaf falls with a gravity ease (s^1.6). Each cell starts after a random stagger of 0–140 ms (flapStaggerMs) so the board ripples.
  • Rendering: a single InstancedMesh draws everything in one draw call, with 3 instances per cell: the upper half, the lower half and the falling leaf. The leaf's front shows the old glyph's top half; its back shows the new glyph's bottom half. Every face comes from one canvas glyph atlas (Helvetica Neue / Helvetica / Arial bold), and wide letters are condensed. The gray split line is painted across the middle of every flap face. The colon is a printed plate with no line. The column labels are HTML and have no line.
  • Master clock: a flap clock at top centre showing h:mm:ss AM, drawn larger (clock.scale 1.45). Since A9 it clacks by default (clock.sound: true); the C key toggles it.
  • Columns, left to right: TRAIN (40) · STATUS (10) · FROM (12) · TO (12) · TIME (HH:MM AM) · GATE (3, right-aligned). The order follows the user's example line (description, status, destination, time), with FROM added. To reorder, rearrange columns in the fields JSON.
  • Status words: ON TIME, DELAYED, BOARDING, ALL ABOARD, DEPARTED, ARRIVING, ARRIVED, CANCELLED.
  • Fun early changes: at +4 s the North Carolina Special becomes DELAYED 10:01 AM (Raleigh), matching the user's example. Also: +9 s gate change, +14 s delay, +20 s gate change, +27 s cancellation, +30 s ARRIVING, +35 s delay. After that, trains depart or arrive and the rows ripple up, and new trains appear at the bottom.
  • Schedule: since A10 it starts at 9:55:00 AM and ends at 6:30:00 PM, then loops (it was 9:58–10:28 AM before A10).
  • Controls:
  • ▶ Forward (runs the clock), ■ Stop, ⟲ Reset (jumps to the start time and keeps the current run/stop state).
  • Speed −/+ in small steps from 0.1× to 60×, plus a 1× button. It starts at 1× (real time) and running.
  • Sound ON/OFF (on by default) and a volume slider (defaults to 100% since A6).
  • Size −/+: scales the clock and flaps only (the headings are fixed), 20–100%, default 70% since A8, remembered per version.
  • Keys: Space = run/stop, R = reset, +/− = speed, 1 = real time, M = mute, C = clock clack on/off, [ ] = board size, I = icon bands on/off (A11).
  • Clock driving: the clock advances with requestAnimationFrame using performance.now() deltas multiplied by the speed. That fixes the A3 bug where Forward didn't advance the clock; this build was verified: stopped Δ = 0, 2 s at 1× ≈ 1.9 s, 2 s at 2× ≈ 3.9 s.
  • Sound:
  • Each flap landing plays a slice of one.wav (sound.slice = 0–0.11 s, the first, sharp metal strike). The second strike at about 0.13 s is skipped; set slice to [0, 0.274] to hear the whole sample.
  • Pitch jitter is ±8%, and the sound is panned left/right by the cell's position.
  • At most 5 voices start per frame (maxVoicesPerFrame), with gain scaled by √n. Everything goes through a compressor, so a whole-board change roars instead of clipping.

Recording a movie (A12)

  • ● Rec from Reset (control bar, or the V key): resets the sign to its start time, sets it running, and starts recording. The button turns red (■ Stop & save movie) and a red counter shows the movie length, size and frame rate. Press it (or V) again: the sound is rendered, the MP4 is assembled and the browser downloads CT40.A12.Solari_YYYYMMDD_HHMMSS.mp4 (normally into Downloads). The note beside the button then says what was saved.
  • What is in the movie: everything above the control bar, exactly as on screen: the flaps and clock (WebGL), the DEPARTURES title and column headings, and both icon bands. The buttons, notes and toasts are not in it. The headings and icon bands are page elements, so A12 paints them onto each movie frame (buildOverlay(): same fonts, letter spacing and positions as the page; the band pictures come from the data-URL copies in icons.js, because drawing the original files from a double-clicked page would block the movie).
  • Speed (harness v4: no batch process, display speed): while recording, every drawn frame advances the sign by exactly 1/fps (flap motion, simNow, and the master clock alike), and frame i is stamped i/fps. So the movie plays at the speed you chose (1× = real time; 30× etc. also work) even when the screen itself runs slower because the computer is encoding. If the encoder falls behind, the sign simply waits a frame; the movie is unaffected. Verified: after 28 / 60 / 93 / 125 frames at 30 fps the sign clock had advanced exactly 0.9333 / 2.0000 / 3.1000 / 4.1667 s, and at 60× exactly 32 frames → +64 s.
  • Resolution: the movie is the window (minus the control bar) at its real device-pixel size, i.e. the canvas buffer, ×1.5 on the user's 150 %-scaled display, up to 3840×2160, made even. 60 fps by default; ?fps=30 for 30.
  • Encoder: constant-quality software H.264 first (?q=18; lower = sharper), then high-bit-rate H.264 profiles, then VP9; each must encode a test frame first (CT54/CT55 lesson: some hardware encoders smear). ?encoder=hw tries the hardware encoder first, ?mbps= sets the bit rate. Chrome/Edge on Windows normally pick H.264 + AAC; the Linux test Chromium had only VP9 + Opus.
  • Sound: every clack the sign plays is logged with its movie time (pitch, pan, gain, the volume slider folded in). On stop, an OfflineAudioContext renders them through the same chain as the speakers (buildChain(): compressor → make-up gain → limiter), in 30 s pieces with 1 s run-up, → AAC (else Opus), exactly as long as the picture. Sound OFF while recording = silence in the movie. The clock clack (C key) is included when it is on.
  • Stop / Forward / Reset / Speed / Size / Icons all still work while recording. Resizing the window mid-take is allowed but the movie keeps its starting size (the picture is scaled into it). If the tab is hidden, recording pauses (the movie just continues when you come back).
  • Test hook: index.html?rec=1 starts recording on opening.
